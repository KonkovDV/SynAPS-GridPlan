## Метрики (измерять одинаково на всех методах)

Считать на одном срезе, одном бюджете времени, одном списке жёстких правил:

- доля работ, для которых построен **проверенный** кандидат;
- число жёстких нарушений чекера (цель тени: понять, какие правила не формализованы);
- число сдвигов **обязательных** заморозок ПЛ (приёмка: 0 на обязательных);
- время подготовки графика относительно **измеренной** базы заказчика (в репо базы нет);
- время разбора одного расхождения экспертом.

Не KPI: SAIDI/SAIFI, N-1, «оптимальность GREED», выручка.

## GO / NO-GO

**GO** только если одновременно:

1. есть именной владелец и письменный состав ограничений;
2. есть обезличенный срез и разрешение на обработку;
3. зафиксированы бюджет времени и критерии приёмки;
4. теневой контур **не** выдаёт команды в SCADA/наряды;
5. бюджет этапа согласован (ниже — гипотеза, не факт оплаты).

**NO-GO:** нет данных; заказчик требует N-1/SAIDI от этого ядра; требуется
аттестат КИИ как вход (его нет); результаты разных датасетов предлагают
сложить в один «эффект».

## Требования ИБ (минимум, не аттестация)

- выгрузка обезличена: без ФИО, табельных, точных адресов жилых домов;
- хранение вне публичного git; срок удаления записан;
- нет обязательных внешних вызовов в контуре расчёта (архитектурное
  наблюдение, **не** соответствие 187-ФЗ);
- не заявлять аттестацию КИИ, ГИС, сертификат ФСТЭК.
