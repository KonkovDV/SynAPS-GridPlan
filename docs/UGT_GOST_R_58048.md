# Матрица УГТ по ГОСТ Р 58048-2017 (самооценка)

Дата: **2026-09-18**. Продукт **0.1.8**. Это **не** сертификат и не заключение
органа по стандартизации.

## Предмет документа

ГОСТ Р 58048-2017 — *Трансфер технологий. Методические указания по оценке
уровня зрелости технологий* (введён 01.06.2018). Карточка:
https://www.gostinfo.ru/catalog/Details/?id=6343929

Стандарт описывает методику уровней готовности (УГТ, УГП и др.), в аннотации
— в том числе авиация и сложные технические системы. Он **не** является
отраслевым сертификатом ПО для электросетевого ТОиР.

ISO 16290:2013 — космические системы и шкала TRL. Текущая константа пакета
`ISO16290_TRL = 4` — самооценка на синтетических фикстурах. **Не подменять**
её формулировкой «ГОСТ Р 58048 УГТ4 закрыт».

Формулировки уровней ниже — по тексту стандарта (лабораторный vs близкий к
реальному). Полный чек-лист ГОСТ содержит десятки индикаторов; здесь —
индикаторы, по которым можно честно судить о **программном** контуре без
выдуманного заказчика.

## УГТ4 — «компонент и/или макет испытаны в лабораторном окружении»

| Индикатор (смысл ГОСТ) | Оценка | Факт в репозитории |
| --- | --- | --- |
| Базовая функциональность в упрощённой (лабораторной) среде | частично да | синтетический РЭС, CI, независимый чекер |
| Макеты частей системы существуют | да (макет) | JSON-фикстуры, `data_provenance=synthetic` |
| Компоненты работают совместно в лабораторном макете | частично да | Python planner + checker; Rust — отдельный контур |
| Контролируемая лабораторная среда | частично да | GitHub Actions, pytest, cargo test |
| Заказчиком определены основные требования | нет | подписанных требований нет |
| Эксперименты с фактическими наборами данных заказчика | нет | живых выгрузок ДЗО нет |
| Договор о намерениях / обязательство заказчика перейти на технологию | нет | — |
| Формальная архитектура ПО, утверждённая заказчиком | нет | внутренние `docs/architecture.md` — архив, не акт заказчика |

**Вывод УГТ4:** лабораторный макет есть; полного УГТ4 по ГОСТ (требования и
данные заказчика) **нет**. Честная формула: «УГТ4-подобная лабораторная
демонстрация на синтетике; самооценка ISO 16290 TRL 4».

## УГТ5 — «компонент и/или макет испытаны в окружении, близком к реальному»

| Индикатор | Оценка | Что закрыло бы |
| --- | --- | --- |
| Испытание в условиях, близких к эксплуатации | нет | shadow-пилот на обезличенной выгрузке одного подразделения |
| Интеграция с поддерживающими элементами заказчика | нет | файловый контур CSV/JSON к процессу ППР, без SCADA |
| Внешние интерфейсы описаны заказчиком (источник, формат, метод поддержки) | нет | контракт данных, подписанный владельцем процесса |
| Утверждённая архитектура ПО системы | нет | ревью с интегратором ДЗО |

**Вывод УГТ5:** не заявляется. Маршрут 4→5 = [`PILOT_ONEPAGER.md`](PILOT_ONEPAGER.md).

## Как проверять, а не декларировать

1. Любая новая самооценка УГТ — строка в [`CLAIMS_REGISTRY.md`](CLAIMS_REGISTRY.md)
   со статусом `assumption` до появления акта заказчика.
2. Не писать «УГТ 5→6» и не переносить космический TRL 5–6 ISO 16290 на сети
   как уже достигнутый.
3. Не сравнивать УГТ GridPlan с УГТ чужого пилота (Hexaly, Hydro-Québec).
