## 1. Что именно делает продукт (границы)

### Делает
1. Берёт перечень работ ТО/ремонта (из 1С:ТОИР / Excel / CSV).
2. Учитывает: бригады и квалификации, окна отключений, предшественников (разборка→диагностика→сборка), переезды/переналадки (SDST), уже согласованные «замороженные» окна.
3. Строит **воспроизводимое** расписание (seed → тот же результат).
4. Отдаёт: расписание, список назначений, `verified_feasible` и протокол нарушений. Dual bound / gap — только если вызван CP-SAT (на РЭС «Северный» makespan 30600 = bound). GREED dual bound не считает.
5. При аварии/срочной заявке — **локальный ремонт** графика без пересборки всего плана (IncrementalRepair / RHC).

### Не делает (и не врём)
- Не заменяет ПРАНА / вибродиагностику / БПЛА-обход.
- Не заменяет 1С:ТОИР / Галактику / АкСиому (учёт, наряды, склад).
- Не заменяет Монитор СК.Заявки (согласование с СО ЕЭС).
- Не делает режимные расчёты N-1 (это ADMS/PowSyBl) — принимает окна допустимости как вход.

**Формула ниши:** `диагностика → [SynAPS] → учёт/согласование`.

## 2. Маппинг «ремонт оборудования» → модель SynAPS

| Реальный объект ТОиР | Сущность SynAPS | Пример |
|---|---|---|
| Работа / операция ремонта | `Operation` | «ТО масляного выключателя ПС-110», «замена лопатки ГТУ» |
| Технологическая последовательность | `predecessor_op_id` | разборка → дефектация → ремонт → сборка → испытания |
| Бригада / пост / стенд | `WorkCenter` (+ `max_parallel` = число смен/постов) | бригада ЭТО, цех КИПиА, пост ГТУ |
| Квалификация / допуск / спецтехника | `AuxRequirement` + aux capacity | «допуск ≥4 гр.», «кран 5 т», «лаборатория масла» |
| Переезд между объектами / смена оснастки | `SetupEntry` (SDST, state→state) | ПС-А → ПС-Б = 90 мин; «горячий/холодный» пуск блока |
| Согласованное окно отключения | `frozen_assignments` | окно СО ЕЭС 12–16.08 нельзя сдвинуть |
| Срок / штраф просрочки | tardiness в objective | штраф за срыв ППР |
| Энергопотери / простой блока | `energy_kwh` / material_loss / makespan | недоотпуск МВт·ч на горизонте ремонта |
| Годовой/месячный горизонт 10K+ работ | RHC в **движке** SynAPS | В продукте GridPlan показан инстанс **55** работ. 10K+ — цель, не демо заявки |

Это уже поддерживается кодом: домен `docs/domains/energy.md`, энергия Wave 10, frozen/RHC Waves 11–14.

## 4. Ценностное предложение (готовые формулировки)

### Проблема (для питча)
Графики ТОиР на станциях и в сетях РФ собираются вручную или в учётных системах без комбинаторного оптимизатора. Документированный разрыв: «РусГидро» заменила IBM Maximo (внутри был CPLEX) на российскую EAM — планирование осталось в Excel. Результат: лишние простои, срывы окон, ручной «пожар» при авариях.

### Решение
SynAPS-GridPlan — **вычислительное ядро** между диагностикой и учётом: автоматически строит и перестраивает график ремонтов оборудования с бригадами, допусками, SDST и замороженными окнами. White-box: каждое назначение объяснимо, график воспроизводим, качество оценено границей.

### Эффекты (что обещать на пилоте — измеримо)
| KPI | Как меряем | Ориентир из литературы / аналогов |
|---|---|---|
| Время составления месячного графика | часы диспетчера до/после | целевой −50…−80% |
| Доля работ, уложенных в согласованные окна | % | рост без нарушений frozen |
| Недоотпуск / простой блока на горизонте | МВт·ч / часы | снижение (цель пилота фиксируется с заказчиком) |
| Переносы уже согласованных окон | шт. | → 0 за счёт frozen-инварианта |
| Восстановление после срочной заявки | минуты до нового feasible графика | vs часы ручной перекладки |

Не обещать снижение недоотпуска / SAIDI как гарантию пилота Россетей. Нет модели последствий заказчика — нет такой цели.

## 5. Архитектура пилота (что реально поставить за 3–6 мес.)

```
[АСУ ТОиР / Excel ППР] ──CSV/JSON──► SynAPS-GridPlan (on-prem)
                                         │
                    GREED / CP-SAT + независимый чекер
                                         ▼
                    график + verified / список нарушений
                                         ▼
```

**Минимальный пилот Россети (рекомендуемый):**

2. П0: исторический месяц → ретро «ваш график vs GridPlan».
3. П1: тень 4–8 недель.
4. П2: операционный цикл на том же участке.

## 8. Конкурентная рамка (только про ремонты)

| Кто | Слой | Мы |
|---|---|---|
| ПРАНА (Мосэнерго ТЭЦ-21/27) | «когда сломается» | берём RUL как вход приоритета |
| 1С:ТОИР (есть у Интер РАО) | учёт нарядов | мы — оптимизатор поверх |
| Монитор СК.Заявки | согласование отключений | мы готовим график к согласованию |
| IBM Maximo Optimizer / Hexaly | мировые аналоги с оптимизацией | ушли / недоступны; нет white-box сертификата |
| Т1 Орсима | generic-оптимизация | нет энергетической предметки ТОиР |

Запрещённая фраза: «аналогов нет».  
Правильная: «мировые аналоги есть, российских класса — не выявлено, в Москве внедрений оптимизатора ремонтов — не обнаружено».
