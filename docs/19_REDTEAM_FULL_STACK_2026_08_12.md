## 3. Подтверждённые ограничения (честно, в limitations)

- **L1. Fan-in/fan-out приоритеты.** SynAPS `Order` — линейная цепочка,
  `predecessor_op_id` одиночный; перекрёстные связи между цепочками солвером
  не представимы. Fail-closed пост-чек ловит (ERROR), но солвер не может
  *учесть* их при построении. Для сетевого ТОиР это терпимо (цепочки
  «ремонт → испытания» линейны); для генерации (энергоблок, веер работ) —
  ограничение. Кандидат: матрица предшествования в ядре SynAPS.
- **L2. Семантика «первое окно»** (из RT-17, подтверждена на уровне кода):
  `release/due = первое одобренное окно`; окна 2+ недоступны солверу (даже
  CP-SAT). Многосуточные окна (реальный кейс «Лопатино», 36 ч) не моделируются.
  Roadmap: window-containment в ядро.
- **L3. ~~`IncrementalRepair` игнорирует `release_date`~~ → RESOLVED (0.1.8, upstream).**
  SynAPS: слот repair ограничен снизу `release_date`; регрессионные тесты на обоих
  уровнях. См. Addendum.
- **L4. Пустой `eligible_wc_ids` = «любая бригада»** в GREED/CP-SAT
  (greedy_dispatch.py:79, 311, 571, 761). Безопасно только потому, что
  пост-чек квалификаций fail-closed. Держать пост-чек под охраной тестов.
- **L5. ЗИП как concurrent pool** в SynAPS; расходуемый остаток — пост-чек.
  Пополнение со временем не моделируется в решателе.

## 4. Соответствие требованиям

### Марафон (критерии жюри)

| Требование | Статус после аудита |
| --- | --- |
| УГТ (TRL) | Честно 3–4: аналитический прототип на синтетике, валидация в лаборатории. Код, тесты 30/30, воспроизводимость, точный режим — сильная сторона пакета |
| Кейс внедрения | РЭС-модель с атомарной привязкой к реальным кейсам 2026 (docs/18) + регламентная мотивация (ПП №86, X-5 16:30) |
| Доказуемость | CP-SAT OPTIMAL + dual bound + fail-closed проверки + отпечатки планов |
| Безопасность заявлений | Все «optimal» — только от CP-SAT; эвристики понижены; синтетика помечена |

### Заказчики (Россети / нормативка)

| Требование | Покрытие |
| --- | --- |
| Окна ПЛ не сдвигать (ПП №86, критерий «плановости») | `FROZEN_ASSIGNMENT_CONFLICT` + freeze-механика repair |
| Квалификации/допуски бригад | aux-ресурсы + пост-чек (даже против пустого eligible) |
| ЗИП на складе | пост-чек расхода + дата пополнения (C2 закрыт) |
| Техпоследовательность | линейные цепочки в солвере + fail-closed пост-чек (fan-in — L1) |
| Недоотпуск/SAIDI | advisory-прокси; честно не в рублях |
| Воспроизводимость для аудита | strict determinism, отпечатки, config_hash |
