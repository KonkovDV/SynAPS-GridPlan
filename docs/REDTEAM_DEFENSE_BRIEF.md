## 1. Solver-эксперт

**Что показать.** Разделение GREED/FIFO (эвристика) и чекера; CP-SAT только
на скомпилированной модели и makespan; адаптер берёт одно окно, не объединение
альтернатив; линейные цепочки, не DAG.

**Ожидаемые удары.**

| вопрос | честный ответ |
| --- | --- |
| GREED оптимален? | Нет. `heuristic_feasible`. Оптимум — CP-SAT на конкретной модели/цели. |
| 107 vs 0 доказывает качество на сети? | Нет. Один синтетический инстанс. |
| Невыполнимость CP-SAT = невыполнимость исходной задачи? | Нет. Потеряны альтернативные окна и полный поиск. |
| Почему нет сравнения с коммерческим MIP на том же JSON? | Можно добавить как эксперимент; чужие датасеты не смешивать. |
| Детерминизм? | Два запуска GREED на jury; CP-SAT — смотреть metadata determinism. |

**NO-GO для текста заявки после этой роли:** любое «оптимально» без solver,
модели и bound.

## 2. Нефтегазовый / электросетевой производственник

Сценарий заявки — **электросетевой ТОиР**, не скважины. Производственник
нужен как носитель цеховой оптики «график vs наряд vs режим».

| вопрос | честный ответ |
| --- | --- |
| Это замена 1С/нарядов? | Нет. Ядро слотов и правил. |
| Окно отключения = разрешённое переключение? | Нет. Вход заказчика; режим вне продукта. |
| ЗИП как на складе? | Сейчас флаг «позиция нужна», не количество BOM. |
| Авария: вы диспетчер? | Синтетические сутки с модельной цепочкой. Не ликвидация режима. Приказ № 289 / СТО 17330282 не «внедрены». |
| Когда вам давать живой ППР? | После ИБ-контура и обезличивания; иначе остаёмся на mock. |

**NO-GO:** обещание безопасности работ, N-1, SAIDI, «как в цехе уже работает».

| вопрос | честный ответ |
