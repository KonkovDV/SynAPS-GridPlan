## A. Календарный FIFO и GREED на аварийном дне

| Показатель | FIFO | GREED |
| --- | --- | --- |
| Работ назначено | 23 / 23 | 23 / 23 |
| Жёстких нарушений | **27** | **0** |
| Проверка | нет | да |
| Время, с | 0.01 | 0.02 |

FIFO, расшифровка:

| Нарушение | Сколько |
| --- | ---: |
| два отключения на одном аппарате | 1 |
| сдвинуто замороженное окно | 1 |
| работа вне окна отключения | 6 |
| нарушена техпоследовательность | 18 |
| старт раньше даты выпуска | 1 |

В аварийный день календарный FIFO даёт недопустимый график (см. расшифровку). GREED строит день восстановления без жёстких нарушений: аварийные окна, полные цепочки «локализация → осмотр → ремонт → опробование → ввод в работу», ЗИП и замороженная заявка ПЛ соблюдены; независимая проверка это подтверждает. Оптимальность не утверждается.

## Как это читать

Сценарий показывает продукт в день массового повреждения: аварийные окна диспетчера,
регламентная четырёхэтапная цепочка на каждом аппарате, приоритет ответственных
потребителей (ДГУ на ФАП первой), жёсткая заморозка согласованной накануне заявки ПЛ
и локальное перепланирование после уточнения объёма работ. Это синтетический
эксперимент; для пилота нужны санитизированные данные сетевой организации.
